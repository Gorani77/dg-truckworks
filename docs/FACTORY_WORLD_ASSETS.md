# 공장 전체 Blender 자산

2026-10-11 (Asia/Seoul). 사용자 요청에 따라 기존 5개 공정 설비 주변의 물리 모형도 Blender 자산으로 전환했다. 새 10종의 편집 원본/GLB 생성 및 연결 코드 작성 완료, 사용자 시각·동작·성능 확인 대기다. Blender 저장/내보내기만 실행했으며 테스트·빌드·린트·렌더·앱 실행·브라우저 검증은 수행하지 않았다.

기존 ST-01/02/03/04/05 자산은 유지했다. 정상 로드 시 공장 건축·주변 시설·운반 구조·생산품의 물리 외형을 Blender 모델로 표시한다. 선택/hover 선, AI 관련 링, 진행률 막대와 HTML 정보 표지는 동적 UI이므로 코드로 유지한다. 로드 대체 모형과 2D 배치도도 유지한다.

## 경로와 연결

- 제작: `assets/source-models/factory-world/create_factory_world.py`.
- 편집: `assets/source-models/factory-world/<자산>/<자산>.blend`.
- 배포: `frontend/public/models/<자산>/<자산>.glb`.
- WorldAsset: URL 로드, 개별 Suspense/SceneBoundary, 장면 복제, 공유 메시/정적 재질, 부품별 품질 재질 복제. 실패한 자산만 기본 모형/실패 안내로 대체한다.
- FactoryEnvironment: 공장 외곽·선반·전시 구역과 기존 클릭 이동/구역 안내.
- FactoryInfrastructure: 서버 설비 수에 따른 생산 바닥 폭과 설비 사이 컨베이어 배치. 기존 장면의 긴 레일과 코드 그리드는 새 컨베이어 프레임/바닥 표식으로 교체한다.
- StationModel: 받침/대기 팔레트/단독 공정 소재와 기존 상태 표현.
- ChassisAsset: RAW/FRAME/DRILLED를 대응 자산에 연결한다. 원본 치수 180 × 60 × 12 mm 기준으로 서버 치수를 반영한다.
- PartModel: 기존 partPosition 결과까지 위치를 보간하고 클릭/추적/서버 품질을 유지한다.

공정 시간·완료·고장·품질·수량은 서버 책임이다. 배경 선반과 카트에 실제 재고를 만들어 넣지 않았다. 전시 트럭은 확장 예정 모형이며 트럭 조립 기능을 구현한 것이 아니다. 벽 조명 발광 재질은 기존 FactoryLighting과 함께 보이며 별도 물리 조명 시뮬레이션은 아니다. 새로운 패키지·원격 자산·유료 자산·API·DB 변경은 없다.

## 사용자가 직접 확인할 절차

1. 기존 로컬 앱을 실행하고 새로고침한다. 전체 보기에서 바닥 이음새/안전선, 낮은 벽/철골/배관이 보이며 기존 설비와 시각적으로 어울리는지 본다. 높아진 디테일이 생산라인을 가리거나 카메라 이동을 방해하지 않아야 한다.
2. 소재 구역을 클릭한다. 선반 브레이싱/기둥과 빈 카트가 보여야 하며 실제 재고로 오해할 수량 표시는 없어야 한다. 트럭 구역에서는 운전석·바퀴·적재함을 보고 “확장 예정·전시 모형” 안내가 유지되는지 본다.
3. 각 설비를 선택한다. 받침과 컨베이어가 중복 없이 표시되고 선택선·상태등·AI 관련 강조가 읽혀야 한다. 바닥 표면의 깜빡임, 그림자 줄무늬, 금속의 과도한 눈부심도 살핀다.
4. 차체 1개 생산을 시작한다. 소재→프레임→구멍 가공 형상이 실제 서버 단계에 맞춰 바뀌고, 부품은 한 번만 표시되어야 한다. 가까운 시점에서 관통 구멍·모서리·공구/부품 높이와 롤러 연결을 본다.
5. 연속 생산에서 대기 팔레트/쌓기와 양품·불량 목적지/색상을 확인한다. 다른 품질의 부품이 있을 때 한 부품의 색상이 다른 부품까지 바뀌면 안 된다. 불량이 실제로 발생하지 않은 실행에서 불량 표시를 기대하지 않는다.
6. 일시정지·가공 중 고장·복구·초기화를 수행한다. 기존 서버 진행률/정지 동작과 부품 선택·추적이 유지되어야 한다. 새로운 배경 때문에 생산 규칙이 바뀌면 안 된다.
7. 필요하면 개발자 도구에서 새 GLB 하나의 요청을 차단하고 새로고침한다. 해당 자산은 기본 모형/실패 안내로 바뀌고 나머지 장면은 유지되어야 한다. 차단 해제 후 새로고침해 다시 로드한다.
8. 작은 화면과 전체 보기↔근접 이동에서 로딩/화면 반응을 직접 살핀다. 이번 작업에서 FPS·전송 크기·성능은 측정하지 않았다. 빌드/린트가 필요하면 `C:\project\truckworks\frontend`에서 `npm run build`, `npm run lint`를 직접 실행한다.

확인 결과와 문제가 생긴 구역/공정/생산 상태를 전달하면 저장된 자산/코드에서 이어서 수정한다. 사용자의 결과를 받기 전에는 검증 완료로 기록하지 않는다.
