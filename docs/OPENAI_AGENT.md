## 결정과 이번 범위

사용자가 OpenAI 사용과 저렴한 모델 선택을 위임했다. 기본 모델은 `gpt-5.6-luna`다. 비용을 우선하는 초기 연결에 사용하며 품질·계정 접근 가능 여부는 실제 호출로 확인해야 한다. 모델 설정은 backend의 환경변수로 바꿀 수 있다. 설정을 임의의 고가 모델로 자동 변경하지 않는다.

2026-10-10 공식 문서의 표준 텍스트 요금은 100만 토큰당 입력 $0.20·캐시 입력 $0.02·출력 $1.20이다. 화면 비용은 응답 사용량과 이 단가로 계산한 추정치이며 실제 청구·환율·세금·실패 요청 비용을 보장하지 않는다. 다른 모델로 설정하면 비용 추정은null로 둔다. [공식 모델 안내](https://developers.openai.com/api/docs/models/gpt-5.6-luna)

LangGraph의 순서는 `select_tools → read_tools → explain`이다. OpenAI Responses API에서 실제 함수 호출을 받아 기존 읽기 도구를 실행하고, 결과를 전달해 한국어 설명을 받는다. 모든 조회는 질문 접수 때의 한 불변 상태를 읽는다. 생산은 분석 중에도 계속 진행하므로 답변은 현재 순간이 아닌 표시된 관측 시점에 대한 설명이다.

## 로컬 설정과 사용자 설치

제공받은 키는 `C:\project\truckworks\backend\.env`의 `TRUCKWORKS_OPENAI_API_KEY`에만 설정했다. 키 값은 문서·예시·소스·프론트엔드에 기록하지 않는다. 기존 DB/CORS 설정은 보존했다. 채팅에 공유한 키는 폐기·재발급하고 같은 환경변수에 새 키를 넣는 것이 좋다. 새 키를 채팅에 다시 보내지 않아도 된다. `.env`는 기존 제외 규칙 대상이다.

```dotenv
TRUCKWORKS_OPENAI_API_KEY=YOUR_NEW_OPENAI_API_KEY
TRUCKWORKS_OPENAI_MODEL=gpt-5.6-luna
```

사용자가 직접 `C:\project\truckworks\backend`에서 실행한다.

```powershell
& "$env:APPDATA\Python\Scripts\uv.exe" sync
& "$env:APPDATA\Python\Scripts\uv.exe" run uvicorn truckworks.api.app:create_app --factory --reload --host 127.0.0.1 --port 8010
```

`uv sync`는 추가한 openai·langgraph 의존성을 설치하고 잠금 파일을 갱신한다. 이번 작업의 DB 마이그레이션은 없다. 기존 저장 기능의 DB 준비·마이그레이션이 아직이면 HISTORY_STORAGE.md를 따른다. 분석은 현재 실행 메모리를 읽으므로 DB 설정 없이도 사용할 수 있다. 키 미설정이면 자연어 요청은503이며 기존 관제·수동 읽기 도구는 유지한다.

## 제한과 실패 처리

- 한 질문은 최대1000자, 모델 요청2회, 도구 최대4회(기본 공장 상태1회+모델이 선택한 최대3회)다. 모델이3회를 초과해 선택하면 추가 실행 없이 실패한다.
- 에이전트 도구의 이벤트 조회는 최대30개다. 누락 여부와 전체 일치 개수를 모델에 전달한다. 수동 조회 API의 기존 최대100개 제한은 유지한다.
- 전체35초, 개별 OpenAI 요청20초, SDK 자동 재시도0회다. 화면 대기는40초다. 한 서버 프로세스에서 분석1건만 허용하고 요청 시작 사이에10초 간격을 둔다. 실패도 비용이 발생했을 수 있어 자동 재요청하지 않는다.
- 모델은 도구 이름과 필터만 선택한다. 실행 ID는 서버에서 고정한다. 모든 도구의 입력·대상 검사를 재사용하며 임의 SQL·시스템 명령·생산 제어는 제공하지 않는다.
- 질문 접수 때 스냅샷·이벤트를 함께 고정한다. 답변 전 실행이 초기화됐으면409로 버리고 새로운 실행의 질문처럼 반환하지 않는다. 이 경우 모델 요청 비용은 이미 발생했을 수 있다. 브라우저 요청 취소도 원격 과금 취소를 보장하지 않는다.
- 답변은 구조화된 설명·한계·근거 이벤트 순번·관련 설비 목록으로 받는다. 근거 순번이 실제 조회된 이벤트에 없거나 설비가 실제 정의에 없으면502다. 이 검사는 인용 대상의 존재를 검사하며 설명 내용의 인과관계까지 자동 입증하지는 않는다.
- 키/접근 권한·한도/결제·네트워크·시간 초과·답변 형식·근거 불일치 실패를 구분해 안내한다. OpenAI 원본 오류·키·응답 본문을 사용자 오류에 넣지 않는다.

성공 응답은 분석 ID·사용 모델·관측 버전·사용 도구와 결과·토큰·캐시 토큰·응답시간·추정 비용을 포함한다. 서버 로그는 성공 요청의 ID·모델·실행·버전·토큰·시간만 기록한다. 질문/답변 전문·도구 인자·원본 오류는 별도 로그로 기록하지 않는다. OpenAI 응답은 store=false로 요청하지만 공급자의 별도 보존 정책까지 무보존이라고 주장하지 않는다.

분석 이력의 DB 영속 저장, 실패/취소 시 부분 사용량 집계, 계정 전체 예산 차단, 공개 서비스 인증/사용자별 제한, 멀티턴 대화, 스트리밍, 과거 DB 실행 분석은 아직 미구현이다. 공개 배포 전 추가 작업으로 남긴다. 현재 프로세스별 제한만으로 전 계정 비용 한도를 보장하지 않는다.

## API

- `GET /api/analysis/status`: enabled·model·busy. 키 설정 여부만 반환하며 실제 인증/모델 연결 검증은 하지 않는다.
- `POST /api/analysis/questions`: expected_run_id UUID·question·선택적 station_id. 결과는 AnalysisResult 모델이다. 404없는 설비,409실행 변경,422입력 오류,429동시 요청/요청 간격,503키 없음,502공급자/형식/근거 실패,504시간 초과다.
- 기존 `/api/analysis/tools/{tool_name}`은 OpenAI를 호출하지 않는 수동 조회다.

## 사용자가 직접 확인할 절차

1. 새 키 설정·uv sync·서버 재시작·화면 새로고침 후 READY에서 “현재 공장 상태를 설명해줘”를 요청한다. 시작 전 상태라는 설명과 실제 도구·관측 시각/버전·사용량이 기대 결과다. 자동으로 생산을 시작하면 안 된다.
2. 20개 생산 중 ST-02를 고장 내고 “선택한 설비가 멈춘 이유와 앞쪽 대기를 설명해줘”를 요청한다. 고장 사실과 대기 영향 추정을 구분하고 실제 상태·고장 이벤트를 근거로 표시해야 한다. 근거 선택 설비 버튼으로 기존 상세/3D 선택이 연결돼야 한다. 분석 자체로 복구하면 안 된다.
3. 공장 일시정지·단독 ST-01 종료·전체 COMPLETED를 각각 질문한다. 사용자 정지·단독 종료·완료를 고장이라고 단정하지 않아야 한다. 현재 조회에 없는 주문/개선율을 만들어내면 안 된다.
4. 부품 질문에서 해당 부품의 실제 이벤트·생략 여부를 확인한다. 답변 순번이 원본 이벤트와 맞아야 한다. 설명이 그 근거로 실제 뒷받침되는지도 직접 확인한다.
5. 분석 도중 초기화하면 이전 결과가 새 실행에 나타나면 안 된다. 분석 완료 뒤 상태가 변했더라도 관측 버전이 표시돼야 한다.
6. 연속 요청·동시 요청429, 잘못된 실행409, 빈 질문/초과 길이422를 확인한다. 키 미설정503·잘못된 키·한도/결제 오류·시간 초과 안내도 필요하면 직접 확인한다. 실패/재시도에는 비용이 발생할 수 있다.
7. 브라우저 개발자 도구에서 요청에는 질문·실행/설비 ID만 있고 OpenAI 키는 없어야 한다. 이 절차의 모든 실제 호출과 검증은 사용자가 수행한다.
