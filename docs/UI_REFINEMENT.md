# UI 표현 정돈 — 2026-10-12

상태: 코드·문서 작성 완료, 사용자 시각·동작 확인 대기. 테스트·빌드·린트·실행·브라우저 확인은 수행하지 않았다.

## 요청과 적용 범위

사용자는 전체 UI의 색감, 장식 화살표, 기계적으로 느껴지는 문구를 실제 웹 서비스 참고로 다듬도록 요청했다. 기존 다크·Pretendard·공장 탐색 구조에서 표면·조작부·설명 방식을 수정했다. 생산 엔진, API, 카메라 동작, Blender 자산, 배포 구성은 변경하지 않았다. 구체적인 시각 만족도는 사용자 확인 전이다.

## 참고 자료와 해석

- [Linear UI 개편](https://linear.app/now/how-we-redesigned-the-linear-ui): 탐색 요소의 정렬과 정보 위계, 시각적 복잡도 감소를 참고했다. 넓은 화면에서 위치와 현황의 상단 행, 하단 조작부의 바를 작성했다.
- [Vercel Geist 색상 체계](https://vercel.com/geist/colors): 배경·상호작용·테두리·텍스트의 색상 역할을 참고했다. 중성 차콜 표면과 공통 토큰을 사용하고 그라데이션·발광 효과를 줄였다.
- [토스의 라이팅 원칙](https://toss.tech/article/21022): 의미 없는 반복을 줄이고 다음 행동을 예상할 수 있는 문구를 쓰는 원칙을 참고했다. 슬로건과 개발자 관점의 설명을 기능·행동 중심으로 바꿨다.

공식 웹 문서를 검색하고 읽어 참고했다. 로그인된 제품 화면을 직접 조작하거나 현재 TruckWorks 화면을 브라우저로 확인한 것은 아니다. 특정 제품을 복제하거나 'AI처럼 보이지 않음'을 검증한 것으로 표현하지 않는다.

## 실제 변경

- `frontend/src/styles/tokens.css`: 중성 배경·텍스트·선, 작은 반경, 단색 표면과 조작색, 가벼운 그림자.
- `frontend/src/app/experience.module.css`: 넓은 화면 상하단 정렬, 로고·조작·분석 진입·정보창의 장식 축소. 좁고 낮은 화면의 기존 분기는 유지.
- `SimulationHud.tsx`, `SimulationExperience.tsx`, `SceneDrawer.tsx`: 장식 화살표/영문 제목/슬로건 제거, 현재 위치·상태·행동 중심 문구. 관련 설비 토글은 표시 켜기/끄기로 행동을 명시.
- `components/Icon.tsx`, `components/button.module.css`: 분석용 말풍선 SVG와 평면 버튼. 의미 있는 고장·가동 색과 분석 설비 강조는 유지.
- `features/agent/SceneAgentPanel.tsx`, `AgentPanel.tsx`, `agent.module.css`: 간결한 질문 선택, 무채색 입력창과 분석 결과 본문, 화살표와 청록 장식 축소. API 비용과 읽기 전용 동작 안내 유지.
- `features/factory/components/`: 공장 지도, 전시 설명, 안내 체험, 환경 조작, 생산 수량 문구 정리. 기능 CSS에 중성 표면 적용.
- `scene/scene.module.css`, `StationMarker.tsx`, `ImmersiveViewport.tsx`: 장면 표지의 단색 표면·분석 아이콘, 로딩 문구 정리. 모델 재질과 가동 로직은 유지.

## 사용자가 직접 확인할 순서

1. 평소 실행 방식으로 화면을 연다. 1440×900 정도의 화면에서는 상단 위치·생산 현황이 한 줄로 정렬되고 하단 조작이 하나의 바에 보여야 한다. 장면 클릭·드래그도 가능해야 한다.
2. 공장 환경, 설비 상세, 지도, 기록, 소개, AI 분석을 각각 연다. 표면색·구분선·글자 위계가 일관되고 내용은 정보창 안에서 스크롤되어야 한다.
3. 생산 시작·정지·재개, 고장·복구, 시점 초기화를 수행한다. 기존 동작을 유지하고 고장/가동 상태가 구분되어야 한다. 환경 조작 대상은 장면 선택과 독립적이어야 한다.
4. AI 질문을 선택하고 필요하면 직접 분석을 요청한다. 질문 선택만으로 요청되지 않아야 하며, 요청에는 기존 OpenAI API 비용이 발생한다. 답변·근거·관련 설비 표시가 동작해야 한다.
5. 390×844, 768px 폭, 낮은 가로 화면에서 메뉴·닫기·생산·분석 버튼이 겹치거나 잘리지 않는지 확인한다. 2D, Tab 초점, Esc, 긴 기록도 살핀다.
6. 연결 전에는 수량이 대시로 표시되고 전시 구역이 실제 생산 가능 상태처럼 보이지 않아야 한다.

필요한 명령은 사용자가 `C:\project\truckworks\frontend`에서 `npm run build`, `npm run lint`, `npm run dev`로 직접 실행한다. 기대 결과는 타입/빌드/린트 오류 없이 실행되고 위 화면·기능 항목이 유지되는 것이다. 현재 성공 결과를 기록하지 않았다.

다음 작업은 사용자 화면 피드백을 받아 밀도·문구·대비를 조정하는 것이다. 다른 레이아웃이나 기능 변경이 필요하면 이유·선택지·영향을 제시하고 선택 후 진행한다.
