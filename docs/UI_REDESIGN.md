# 공장 전체 UI 개편 안내

2026-10-11 (Asia/Seoul). 사용자가 첨부한 설비 표지·상단 현황·하단 생산 버튼을 포함해 모든 UI의 재디자인을 요청했다. 기존 공장 탐색과 서버/AI 기능을 유지하는 범위에서 코드·스타일 작성 완료, 사용자 시각/동작 확인 대기다. 테스트·빌드·린트·앱 실행·브라우저 검증·스크린샷 촬영은 수행하지 않았다.

| 상단 | 브랜드/연결 상태, 아이콘 메뉴, 현재 탐색 위치, 상태등과 분리된 양품/불량/시뮬레이션 시간 |

| 기타 | 첫 진입/소개/체험 단계, 로딩, 오류, 상태 알림, 2D 대체, 공통 패널/기존 보조 화면 스타일 |

모델/서버 생산 규칙/이력 저장/API 비용 정책은 변경하지 않았다. 실제 수신하지 않은 숫자나 AI 진행 단계를 만들지 않았다. 공정 진행률은 기존 잔여시간과 처리시간에서 계산한다. 안내 단계는 기존 서버/분석 응답 조건을 따른다. 연결 전 수량은 —로 표시한다.

## 직접 확인할 절차

1. 기존 앱을 새로고침하고 전체 보기→라인→설비→차체를 탐색한다. 새 표지의 연결선/크기/가림과 텍스트 가독성, 선택/가리킴 때 정보 확장을 살핀다. 상태는 점 색상과 한국어 문구로 함께 표시되어야 한다.
2. 기록/소개/설정/AI 버튼을 열고 다시 눌러 닫는다. 선택된 메뉴 표시가 실제 열린 창과 맞아야 한다. 창 안은 스크롤할 수 있고 배경3D의 탐색은 유지되어야 한다.
3. 1개/20개 생산 시나리오를 생산 설정에서 선택한다. READY일 때만 선택 가능하고, 기존처럼 시작/정지/재개/초기화/고장/복구가 올바른 상태에서 활성화되어야 한다. 하단 기본 시작은 기존처럼 20개 생산이다.
4. 설비 상세에서 남은 처리/입력 대기/이동 예약을 보고 접힌 상세를 열어 설정값·현재 부품 ID·FIFO를 읽는다. 차체에서는 수신된 RAW/FRAME/DRILLED에 맞는 단계가 표시되어야 한다.
5. AI 버튼과 대상/추천 질문/입력/답변/관련 설비/근거·수동 조회를 확인한다. 실제 분석은 사용자가 원하는 경우만 요청하며 기존 OpenAI 비용이 발생한다. 이번 개편에서 API를 호출하지 않았다. 요청 중에는 대기 안내만 표시하고 사용하지 않은 도구 단계를 가짜로 보여주지 않는다.
6. 기록의 세 탭과 조회/필터/페이지 조작, 빈 목록/연결 대기/에러를 확인한다. 분석 목록의 선택 표시와 상세 결과가 일치해야 한다. 과거 자료를 현재 상태로 표현하면 안 된다.
7. 전체 보기에서 안내 체험과 소개의 조작 흐름을 살핀다. 좁거나 낮은 화면에서는 정보창·체험 내용의 내부 스크롤을 사용한다. 가로로 매우 낮은 화면의 안내 오버레이는 기존처럼 숨긴다.
8. 1440px급 데스크톱, 768px 전후, 390px/320px 폭, 낮은 높이에서 상단·하단·창이 겹쳐 버튼을 가리지 않는지 본다. 2D 전환과 시점 복귀도 확인한다. 글자를 확대했을 때 긴 설비명/질문/ID의 줄바꿈을 살핀다.
9. 키보드 Tab/Enter/Space, 탐색 select, Esc 닫기/복귀, 창 제목으로 초점 이동/닫은 뒤 복귀를 확인한다. 아이콘 버튼에는 텍스트나 접근 가능한 이름이 있어야 한다. OS의 모션 감소 설정에서 장식 애니메이션은 꺼져야 한다.
10. 필요한 경우 `C:\project\truckworks\frontend`에서 `npm run build`, `npm run lint`를 직접 실행한다. 이 문서는 성공 결과를 의미하지 않는다.

가림/간격/색상 문제가 있으면 화면 크기, 열린 창, 공장 상태와 함께 알려주면 이어서 조정한다. 첨부 이미지에서 사용자가 평가한 것은 이전 모델링의 개선과 UI 불만이며, 새 UI 검증 완료로 기록하지 않는다.
