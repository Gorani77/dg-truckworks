# 공장 환경 중심 화면 — A안

2026-10-12 (Asia/Seoul). 사용자 A안 선택에 따른 코드·문서 작성 완료, 사용자 확인 대기. 테스트·빌드·린트·서버 실행·브라우저 검증·AI 호출은 수행하지 않았다.

## 이번 범위

- 좌측 공장 환경 메뉴에서 장애 설정과 기존 생산 제어를 제공한다. 조작할 설비는 장면 선택과 별도로 유지하며 고장·복구는 기존 API를 사용한다.
- 설비·차체 상세는 정보만 표시한다. 고장·복구·개별 AI·차체 추적 버튼을 제거했다. 차체 추적은 장면의 차체 클릭 또는 환경 메뉴의 차체 선택으로 가능하다.
- 상단 현재 선택 위치는 텍스트로만 표시한다. 기존 드롭다운과 상위 이동 버튼을 제거했다. 공장 지도는 유지하며 키보드용 설비 목록을 그 안에 제공한다.
- 공통 AI 공장 분석은 장면 선택 설비를 요청에 자동 전달하지 않는다. 전시 구역에서도 열 수 있지만 실제 데이터는 차체 생산라인만 포함한다. 자동 분석 호출은 추가하지 않았다.
- 안내 체험의 고장/복구 단계는 환경 메뉴를 열어 ST-02를 조작 대상으로 지정한다. 실제 명령은 사용자가 환경 메뉴의 버튼으로 실행한다.
- 환경 조건에 따른 고장 모델, 임계값, 새로운 센서 데이터는 구현하지 않았다. 기존 수동 고장 원인을 실제 온도·마모 등으로 설명할 근거는 없다.

## 사용자가 직접 확인할 절차와 기대 결과

기존 로컬 실행 방법은 루트 README와 backend/README를 따른다. 이번에는 새 패키지·환경변수·DB 변경이 없다. 프론트엔드는 C:\project\truckworks\frontend에서 필요 시 npm run dev로 실행한다.

1. 첫 화면에서 좌측 공장 환경을 연다. 장애 대상 선택과 고장/복구, 생산 시나리오·시작·정지·재개·초기화가 같은 왼쪽 정보창에 있어야 한다. 생산 시작 전에는 고장/복구가 비활성이다.
2. 환경 메뉴에서 ST-02를 선택한다. 메뉴를 닫고 장면의 ST-03을 클릭한다. 상세창에는 상태와 수치만 있고 고장·복구·AI·차체 추적 버튼은 없어야 한다. 다시 환경 메뉴를 열면 조작 대상은 ST-02로 유지되어야 한다.
3. 20개 생산을 시작하고 ST-02에 고장을 발생시킨다. ST-02가 고장으로 표시되고 다른 설비와 이동은 가능한 범위에서 진행되어야 한다. 고장 버튼은 비활성, 복구는 활성으로 바뀌어야 한다. 상단 위치와 카메라는 환경 대상 선택/명령만으로 바뀌지 않아야 한다.
4. 다른 설비를 관찰한 상태에서 하단 AI 공장 분석 또는 고장 알림을 연다. 분석 범위는 현재 가동 공장·차체 생산라인이고 특정 선택 설비가 자동 지정되지 않아야 한다. 실제 요청을 원하면 분석 요청을 누르고, 브라우저 네트워크의 /api/analysis/questions 요청에 station_id가 없는지 직접 확인한다. 이 요청은 기존 OpenAI 호출 비용이 발생한다.
5. AI 없이 공장 자료 직접 조회를 펼쳐 공장 현황·전체 최근 이벤트·전체 대기/예약을 조회한다. 선택 설비 필터 없이 결과를 볼 수 있어야 한다. 모델 답변은 실제 상태/이벤트 근거를 살펴 평가하며 새 환경 고장 원인이 구현된 것으로 해석하지 않는다.
6. 좌측 환경에서 ST-02를 복구한다. 일시정지 중이라면 생산 제어에서 재개한다. 복구는 보존된 작업을 이어가고 공장 재개만으로 고장이 해제되지는 않아야 한다.
7. 장면의 구역·설비·차체를 클릭한다. 상단 이름이 바뀌며 위치 표시 자체에는 드롭다운이나 상위 이동 버튼이 없어야 한다. 기존 휠 배율/각도 보존과 시점 초기화도 직접 확인한다.
8. 소개에서 안내 체험을 시작한다. 고장/복구 안내는 환경 메뉴만 열고 명령을 자동 실행하지 않아야 한다. 실제 수신 상태와 분석 응답에 따라 다음 단계로 진행되어야 한다.
9. 공장 지도 안의 설비 목록과 환경 메뉴를 Tab/Enter로 사용한다. 2D에서도 정보 선택과 환경 조작이 분리되어야 한다. 320px·390px 폭과 낮은 화면에서 메뉴/닫기/내부 스크롤/하단 조작을 사용할 수 있어야 한다.
10. 연결 전/끊김에는 현재 수치가 수신 대기로 바뀌고 생산·고장·복구가 비활성화되어야 한다. 명령 실패는 환경 메뉴 안에 오류가 보여야 한다. 실행 초기화 후 이전 분석과 안내 단계가 새 실행에 남지 않아야 한다.

필요하면 사용자가 frontend에서 npm run build와 npm run lint를 직접 실행한다. 기대 결과는 오류 없이 종료되는 것이다. 이 문서는 확인 절차이며 통과 기록이 아니다.
