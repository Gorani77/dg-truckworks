# 관제 화면과 단일 설비 API 연결

작성일: 2026-10-08 (Asia/Seoul)

## 연결 범위

- Vite 개발 서버가 `/api` 요청을 `http://127.0.0.1:8010`으로 전달한다. 설정 변경 후 프론트엔드 개발 서버를 재시작한다.
- 화면 진입 시 상태 GET 후 이벤트 GET을 순서대로 요청한다. 응답 후 약 300ms 뒤 다시 조회하며 실패 시 약 1.5초 뒤 재시도한다. 요청당 제한 시간은 5초다.
- 실행 상태, 소재 잔여, 라인 내부 부품, 양품·불량·입력 대기, 시뮬레이션 시간과 선택 설비의 부품 ID·남은 시간이 서버 응답으로 표시된다.
- 수신한 설비 정의로 목록·상세·배치도의 설정을 표시한다. 응답 전·연결 실패 시 기존 정적 설비 정의는 모델 미리보기로 유지하고 생산 수치는 `—`로 표시한다.
- READY일 때만 `소재 1개 처리 시작` 버튼이 활성화된다. 시작 시 ST-01이 선택되고 현재 run_id를 POST 본문으로 전송한다. 요청 중에는 버튼을 비활성화한다.
- 시작 POST는 자동으로 재전송하지 않는다. 응답 실패 시 실제 서버 처리는 시작됐을 수 있으므로 상태를 다시 조회해 표시한다. 서버도 같은 실행의 중복 시작을 거절한다.
- 상태와 이벤트를 별도로 읽으므로 두 요청 사이에 상태가 바뀔 수 있다. 표시할 이벤트는 상태와 같은 run_id이고 해당 last_event_sequence 이하인 항목으로 제한한다. 다음 조회에서 최신 항목이 반영된다. 두 API의 원자적 조회를 구현한 것은 아니다.
- 요청 실패 시 이전 상태·이벤트를 지우고 연결 끊김과 오류를 표시한다. 재연결 후 서버의 현재 실행을 읽는다.
- 화면 이탈·effect 정리 시 조회와 예약 타이머를 취소한다. 시작 시 진행 중 조회를 취소해 시작 전 응답이 화면을 덮지 않게 한다.

이번 연결은 HTTP 기반이다. 후속 작업에서 기본 3D 장면과 상태 표시 코드를 작성했으며 사용자 확인 대기다. 설치와 확인은 [FACTORY_3D.md](FACTORY_3D.md)를 따른다. WebSocket·다음 공정 이동·일시정지·재개·초기화·고장·에이전트는 후속 기능이다. 관제 화면은 서버에 시간을 진행시키는 명령을 보내지 않는다.

## 나중에 사용자가 확인할 순서

백엔드 설치·실행은 [SINGLE_STATION.md](SINGLE_STATION.md)의 명령을 사용한다. SimPy 설치를 위한 uv sync가 필요하다. 프론트엔드는 `C:\project\truckworks\frontend`에서 `npm run dev`로 실행한다. 이미 실행 중이었다면 종료 후 다시 실행한다.

1. 화면을 연다. `서버 연결됨`, `시작 대기`, 소재 잔여 20, 생산 수량·시간 0이 기대 결과다.
2. `소재 1개 처리 시작`을 누른다. ST-01이 선택되고 소재 19·라인 내부 1·처리 중·남은 시간이 표시돼야 한다.
3. 약 2초 후 `단일 처리 종료`, ST-01 `출력 대기`, 시간 2.0초·남은 시간 0.0초가 기대 결과다. 양품·불량·입력 대기는 모두 0을 유지한다.
4. 이벤트 표에 시작·완료 두 행이 나타나야 한다. 설비 ID에 마우스를 올리면 부품 ID를 볼 수 있고, 우측 상세의 ID와 일치해야 한다.
5. 처리 중·종료 후에는 시작 버튼이 비활성화된다. 다른 공정을 선택하면 해당 설비는 대기 상태이고 공정 정의와 상세가 함께 바뀌어야 한다.
6. 브라우저를 새로고침해도 서버를 재시작하지 않았다면 같은 완료 상태와 이벤트가 다시 표시돼야 한다.
7. 백엔드를 종료하면 연결 끊김·오류가 표시되고 수치가 `—`, 이벤트는 수신 대기로 바뀌어야 한다. 요청 제한 시간 때문에 표시까지 시간이 걸릴 수 있다.
8. 백엔드를 다시 실행하면 자동으로 초기 상태·소재 20·빈 이벤트로 돌아오고 시작 버튼이 활성화돼야 한다. 이전 이벤트를 새 실행에 섞지 않아야 한다.
9. 화면 폭을 줄여 늘어난 현황 항목과 긴 부품 ID가 패널을 넘지 않는지 확인한다.

기존 다크 테마·글꼴·공정 선택 확인 완료 기록은 이전 화면 버전에 대한 것이다. 이번 연결 변경의 사용자 확인을 대신하지 않는다. 원하면 lint·build도 사용자가 직접 수행한다.

## 파일과 데이터 흐름

`src/api/factory.ts`(HTTP·서버 응답 타입) → `features/factory/hooks/useFactoryConnection.ts`(조회·취소·연결 상태·시작 명령) → `app/FactoryDashboard.tsx`(화면에 전달) → 현황·제어·상세·이벤트 컴포넌트.

`features/factory/presentation.ts`가 서버의 snake_case 정의를 기존 화면 모델로 변환하고 상태 표시명을 관리한다. TypeScript 타입은 서버 응답에 대한 런타임 스키마 검사를 대신하지 않는다. 현재 클라이언트는 자체 백엔드의 응답 계약을 사용하며 완전한 런타임 응답 검사는 추가하지 않았다.

Codex는 설치·테스트·빌드·린트·실행·브라우저 검증을 수행하지 않았다.
