# 네 설비 Blender 확장 확인 안내

2026-10-11 (Asia/Seoul). ST-02 시각 품질에 대한 사용자의 긍정 피드백 이후 나머지 네 공정을 제작했다. 모든 새 `.blend`/`.glb` 생성과 연결 코드 작성 완료, 사용자 시각/가동 확인 대기. 테스트·빌드·린트·렌더·브라우저·성능 측정은 수행하지 않았다.

## 추가한 외형과 동작

| 설비 | 외형 | 서버 진행률 기반 동작 |
|---|---|---|
| ST-01 | 빈 매거진/슬롯, 리프트 가이드, 흡착 컵, 제어함 | 흡착 헤드 하강·복귀 |
| ST-03 | 컬럼/레일, 모터/척/드릴, 고정 지그, 측면 가드 | 지그 고정·위치 이동·드릴 하강/복귀·해제 |
| ST-04 | 검사 포털, 조명 바, 렌즈/카메라, 센서 프레임 | 검사 헤드와 스캔 띠 이동 |
| ST-05 | 분리 가이드/구동부, 롤러 슈트, 양품/불량 트레이 | 현재 부품의 서버 품질값에 맞춘 가이드 회전 |

도장·금속·고무·안전창·상태등은 ST-02 계열 재질이다. 빈 매거진에 가짜 재고를 쌓지 않으며 실제 생산품은 기존 PartModel이 한 번만 표시한다. 트레이 중심은 기존 분리 부품 경로와 맞춘 (x=1, z=.45±1.9), 바닥 높이는 .38이다. 트레이는 기존 차체 길이1.8에 맞춰 넓혔다. 기존 엔진 수량/품질/좌표 계산은 바꾸지 않았다.

가동 노드 위치는 서버 진행률의 함수다. 일시정지 때 시간이 독립적으로 흐르지 않으며 가공 중 고장은 기존 holdProcessPose로 수신 포즈를 유지한다. 검사 광선은 실제 비전 알고리즘이나 측정 결과가 아닌 연출이다. 드릴의 여러 접근 동작도 기존6초 공정 안의 표현이며 새로운 엔진 공정은 아니다.

## 사용자가 직접 수행할 절차

1. 기존 방식으로 실행해 전체 공장과 각 설비 가까운 시점을 살핀다. 다섯 설비의 소재/외형 스타일이 연결되어야 하고 테이블/상태등이 중복 표시되지 않아야 한다.
2. ST-01에서 빈 슬롯과 흡착 헤드를 본다.1개 생산에서 실제 소재가 한 번만 표시되고 헤드가 내려왔다 복귀해야 한다.
3. ST-03에서 지그 고정·드릴 위치 이동·하강·복귀를 확인한다. 가공 끝에 기존 서버 부품 형상이 DRILLED로 바뀌어야 한다. 공구 관통/가림과 시각적 자연스러움은 사용자 판단 대상이다.
4. ST-04에서 처리 중에만 스캔 띠가 나타나고 헤드와 함께 움직이는지 본다. 품질 결과는 기존 서버가 판정하며 화면이 임의로 만들면 안 된다.
5. ST-05에서 양품/불량이 기존 목적지로 이동하고 가이드 방향이 품질에 맞아야 한다. 실제 발생한 품질만 확인하고 임의로 불량이 나왔다고 기록하지 않는다. 적재품과 트레이의 위치/크기도 살핀다.
6. 각 가공 중 일시정지→재개와 고장→복구를 직접 수행한다. 수신 포즈/잔여시간/부품이 유지되어야 하고 고장등은 고장 색으로 표시되어야 한다. 초기화하면 대기 포즈로 돌아가야 한다.
7. 모델 하나의 요청만 개발 도구에서 차단 후 다시 연다. 해당 설비는 기존 도형과 안내로 대체되고 나머지3D·선택·AI 강조·생산 제어는 유지되어야 한다. 차단 해제 후 새로고침한다.
8.20개 생산과 부품 추적, 전체/상세 시점에서 조작성과 느려짐을 살핀다. 필요하면 frontend에서 `npm run build`와 `npm run lint`를 직접 수행한다. 이 문서는 성공 결과가 아닌 확인 안내다.

## 파일과 재개

원본/제작 방법은 `assets/source-models/equipment/README.md`, 런타임은 EquipmentAsset·equipmentMotion·ProcessEquipment·StationModel·FactoryScene이다. ST-02는 기존 FormingCellAsset 경로를 유지한다. 새 npm 의존성·백엔드·DB 변경은 없다.

중단 시 `MODELING_CHECKPOINT.md`와 실제 저장 파일에서 이어간다. 생성 성공, 코드 작성, 사용자 확인을 각각 구분해 기록한다. 현재 다음 작업은 사용자 피드백 반영이다.
