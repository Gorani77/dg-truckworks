# 완성형 공장 시각 마스터플랜

작성일: 2026-10-11 (Asia/Seoul)
상태: 새 Blender 자산8종 저장/내보내기 완료, 장면·메뉴 코드 작성 완료. 사용자 시각·동작·성능 확인 대기.

## 사용자가 확정한 범위

지금 동작하지 않는 설비도 최종 생산 흐름을 보여줄 수 있도록 모델링과 메뉴를 먼저 만든다. 완성 트럭의 운행 시뮬레이션, 운행 전 AI의 결과 예측은 최종 목표로 기록하되 이번에 엔진·예측 기능을 구현하지 않는다.

기존 공장은 차체 설비5개와 소재/조립 전시를 포함한3개 구역이었다. 이번에는 자체 설계한 모형 공장을9개 구역으로 넓혔다. 실제 자동차 제조 공장의 모든 공정을 복제한 CAD나 검증된 설비 배치가 아니다. 공급 부품인 바퀴·차축·운전석을 전부 자체 제조한다고 바꾸지 않고 부분조립/마감 구역으로 취급한다.

## 구역과 모형

| 구역 | 물리 모형 | 현재 동작 |
| --- | --- | --- |
| 01 입고·소재 보관 | 기존 선반, 입고 공간, 카트 | 정적 전시 |
| 02 차체 생산라인 | 기존 ST-01~05, 컨베이어, 차체 | 기존 생산·고장·복구·AI 기능 유지 |
| 03 차축·휠 부분조립 | 휠 랙, 차축 지그, 압입/체결 갠트리, 제어반 | 정적 전시 |
| 04 운전석 마감 | 마감 부스, 집진기, 로봇, 운전석, 장착 작업대 | 정적 전시 |
| 05 트럭 최종조립 | 차체 리프트, 장착 갠트리, 체결 로봇, 공구함, 프레임/완성 트럭 | 정적 전시 |
| 06 트레일러 제작 | 프레임 지그, 바퀴/랜딩기어, 적재함/리브, 체결 로봇 | 정적 전시 |
| 07 완성차 검사 | 조명 포털, 휠/제동 롤러, 광학 센서, 제어반, 차량 | 정적 전시, 검사 수치 없음 |
| 08 완성차 출하 | 도크/셔터, 주차 베이, 전시 트럭, 포장 상자 | 정적 전시, 실제 재고 아님 |
| 09 주행 시험장 | 순환 트랙, 차선, 연석, 출발선, 콘, 관측실, 차량 | 정적 전시, 물리/운행 없음 |

전체 기반도 campus-ground로 작성했다. 넓은 기초/이음새, 물류 통로, 낮은 절개 벽, 철골/배관, 제어함, 야드 조명/식재를 배치한다. 기존 차체 생산 좌표는 그대로 두고 주변 구역을 넓혔다. 기존 factory-hall/assembly-display 파일은 보존하며 새 몰입형 장면은 campus-ground/final-assembly를 사용한다.

## 제작과 연결

- 스크립트: assets/source-models/full-factory/create_full_factory.py
- 새 자산: campus-ground, axle-cell, cab-finishing, final-assembly, trailer-cell, vehicle-inspection, dispatch-yard, proving-ground
- 원본: assets/source-models/full-factory/<이름>/<이름>.blend
- 웹: frontend/public/models/<이름>/<이름>.glb
- 원본은 개별 부품을 유지하고 웹용은 부모/재질별 메시를 합친다. glTF Y-up, 정적 내보내기. 새 패키지나 외부 유료 자산 없음.
- frontend/src/scene/factoryCampus.ts: 좌표·모델·시점 범위·설비 목록·미구현 행동을 한 곳에서 관리.
- FactoryEnvironment: 개별 WorldAsset 로드와 모형/표지 클릭 이동, 모델별 로드 실패 대체.
- SpatialCamera/FactoryScene/FactoryLighting: 큰 공장 전체 보기·구역별 근접 시점·깊이/조명 범위 반영. 기존 생산 위치/엔진은 유지.
- SimulationHud/CampusMenu: 전체 지도,9개 구역, 기존5개 실행 설비, 향후 AI 예측 진입을 연결.
- FutureZoneDetails: 각 구역 설비 설명과 비활성 실행 메뉴, 기능 예정 상태 명시.
- ImmersiveViewport: 2D 대체에서도 전체 구역 메뉴 제공. 기존 차체 배치도 유지.

비동작 구역에서는 생산 조작 대신 차체 라인 이동을 제공하고, 기존 차체 AI 버튼을 비활성화한다. 상단 수치는 차체 라인 수치임을 표시한다. 전시 차량·바퀴·상자 등을 서버 생산량이나 재고로 집계하지 않는다.

## 후속 목표 — 이번에는 미구현

완성 트럭 선택 → 운행 조건 설정 → AI 사전 예측 → 운행 시뮬레이션 → 예측/결과 비교라는 연결을 목표로 한다. 조건·지표·물리 모델·예측 방식은 후속 설계 대상이다. 임의 예측값, 가짜 운행 결과, 실제 모델 호출, 조립/출하 API를 추가하지 않았다.

## 사용자가 직접 확인할 절차

1. 기존 앱을 실행해 공장 전체에서 9개 구역과 통로가 보이는지 확인한다. 새로고침 후 모델 다운로드 시간이 늘어날 수 있으며 성능은 아직 측정하지 않았다.
2. 공장 지도·현재 탐색 메뉴·구역 표지를 각각 사용해 이동한다. 전체 시점에 캠퍼스가 들어오고 각 구역에서 필요한 모형이 보여야 한다.
3. 차축 지그/부스/리프트/트레일러/검사 롤러/출하 도크/트랙의 디테일, 설비 배치 겹침, 표지 가림, 그림자/재질을 직접 본다.
4. 미구현 구역은 설비 설명과 기능 예정 버튼을 보여야 한다. 생산·차체 AI 명령을 해당 구역의 기능인 것처럼 실행하면 안 된다. AI 예측 메뉴에는 향후 흐름만 있어야 한다.
5. 차체 라인에서 기존 생산·고장·복구·AI·부품 추적·기록을 확인한다. 생산 좌표/백엔드 규칙이 바뀌지 않아야 한다.
6. 2D 전환과 키보드 탐색으로 9개 구역에 접근하고, 모바일 전체 보기에서는 작은 번호 표지/공장 지도로 이동하는지 확인한다.
7. 필요하면 새 GLB 한 개를 브라우저에서 차단하고 재시작해 해당 자산만 대체 모형/실패 안내로 표시되는지 확인한다.
8. frontend에서 npm run build / npm run lint를 사용자가 직접 실행한다. FPS·메모리·로딩은 실제 기기에서 직접 확인한다.

에이전트가 수행한 실행은 Blender 자산 제작·저장·내보내기뿐이다. 테스트·빌드·린트·렌더·앱/서버 실행·브라우저 검증은 수행하지 않았다. 다음은 사용자 피드백에 따른 모형/시점/메뉴 조정이다.
