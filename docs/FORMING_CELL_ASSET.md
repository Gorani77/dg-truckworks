# Blender 형상 가공기 대표 모델

2026-10-11 (Asia/Seoul). 사용자 승인에 따라 ST-02 한 대를 Blender 기반의 대표 설비로 제작했다. `.blend` 저장과 `.glb` 내보내기는 수행했고 프론트 연결·조명·동작 코드를 작성했다. 사용자 시각/동작 확인 대기이며 테스트·빌드·린트·앱 실행·브라우저 검증·Blender 렌더·성능 측정은 하지 않았다.

## 이번 범위

기존 코드 도형 가공기를 전용 GLB로 바꾸고, 외장/모서리·안전창·테이블·레일·공구·지그·제어판·배선의 구조와 도장/금속/고무/투명 재질을 구분했다. 모델은 생산 과정이 보이는 절개 모형이며 실제 CNC의 정밀 구조·절삭·안전 동작을 재현한 것으로 소개하지 않는다. 다른 네 공정의 모델은 이번 대표 모델 제작 범위에 포함하지 않는다.

형상 가공기의 기본 테이블과 상태등은 GLB에 들어 있으므로 기존 공통 테이블/상태등의 중복 표시를 제외했다. 생산품, 공정 간 이동, 입력 대기, 설비 선택, AI 강조는 기존 표현을 유지한다. 모델 로딩 중/실패 시 해당 설비만 기존 도형과 안내 문구로 대체한다.

## 파일과 책임

- `assets/source-models/forming-cell/create_forming_cell.py`: 자체 모델 제작·원본 저장·재질/가동 부모별 웹용 메시 합치기·GLB 내보내기.
- `assets/source-models/forming-cell/forming-cell.blend`: 편집 원본.
- `frontend/public/models/forming-cell/forming-cell.glb`: 앱이 직접 제공하는 배포 파일.
- `scene/equipment/FormingCellAsset.tsx`: 로드·재질 분리·가동 노드 참조·상태등·부분 실패 대체.
- `scene/equipment/formingCellMotion.ts`: 서버 진행률→지그/공구 목표 위치. 생산 시간·수량·품질을 결정하지 않는다.
- `scene/equipment/ProcessEquipment.tsx`, `scene/StationModel.tsx`: ST-02만 새 모델로 연결, 공통 테이블/상태등 중복 제거.
- `scene/FactoryLighting.tsx`, `FactoryScene.tsx`, `sceneConfig.ts`, `styles/tokens.css`: 환경광을 줄이고 주광/윤곽 조명·로컬 생성 반사 환경을 적용. 조명은 공장 전체에 영향을 준다. 새 원격 HDR·패키지는 없다.

## 동작

| 서버 가공 진행률 | 표현 |
|---|---|
| 0–12% | 지그 고정 |
| 12–24% | 공구 접근 |
| 24–76% | 가로 가공 이동 |
| 76–90% | 공구 상승 |
| 90–100% | 지그 해제·가로 위치 복귀 |

이 구간은 시각적 연출 분할이며 별도 엔진 공정이 아니다. 상태 수신 없이 실제 시간을 더해 가공을 진행하지 않는다. 가공 중 고장은 기존 remaining_process_seconds와 status_before_fault의 포즈를 유지하고, 일시정지는 수신 진행률이 변하지 않으므로 같은 포즈를 유지한다. 가공 외 상태는 대기 포즈이며, 고장 상태등은 별도로 고장 색을 표시한다.

## 사용자 확인 절차와 기대 결과

1. 기존 로컬 실행 방법으로 앱을 연다. 공장→차체 라인→ST-02 형상 가공기를 선택한다. 둥글게 가공된 외장 모서리·패널·안전창·지그·제어판이 나타나고, 바닥/작업대가 이중으로 겹치지 않아야 한다.
2. 가까이 회전하며 도장/금속/고무/유리의 구분, 작업면 가시성, 반사/그림자, 화면 글자와 가공기의 가림을 살핀다. 다른 설비와 공장 전체의 밝기도 함께 확인한다. 실제 만족도는 사용자 판단 항목이다.
3. 차체1개를 생산해 소재가 기존 컨베이어 높이에서 진입하고 가공 후 이동하는지 본다. 모델에 내장한 가짜 소재가 겹쳐 나타나면 안 된다.
4. 지그 고정→공구 접근→가로 이동→상승→해제 순서와 공구/소재의 위치를 확인한다. 실제 절삭/충돌 물리를 적용한 모델은 아니다.
5. 가공 중 일시정지 후 기다린다. 공구와 지그가 계속 진행하면 안 된다. 재개하면 수신 진행률부터 이어져야 한다. 가공 중 고장과 복구에서도 기존 부품/잔여시간이 유지되고 상태등이 바뀌어야 한다.
6. 초기화 후 공구·지그는 대기 포즈로 돌아가고 이전 부품은 사라져야 한다. 설비 클릭·AI 관련 강조·부품 추적은 기존 기능과 연결되어야 한다.
7. 필요한 경우 브라우저 개발 도구의 요청 차단으로 모델 URL만 차단한 뒤 다시 연다. ST-02는 기본 도형과 실패 안내로 대체되고 다른 공장 장면/조작은 유지되어야 한다. 해제 후 새로고침하면 모델을 다시 요청한다.
8. 사용자가 원하는 화면 크기에서 회전/확대/20개 생산을 직접 보며 느려짐을 확인한다. 이번 작업에서 FPS·GPU 메모리·로드 시간을 측정하지 않았다. 원하면 frontend에서 `npm run build`, `npm run lint`를 직접 실행한다.

편집 원본은 Blender로 직접 열 수 있다. 포터블 위치와 재생성 명령·가동 노드 이름은 원본 폴더 README에 기록했다. 모델 생성 스크립트를 재실행하면 직접 수정한 원본을 덮어쓰므로 별도 편집본으로 보관한다.
