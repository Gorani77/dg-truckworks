# TruckWorks 소개 초안

작성일: 2026-10-11 (Asia/Seoul). 문서 작성 완료·사용자 내용 검토 대기. 공개 호스팅 선택은 보류됐고 실제 데모 배포·영상 제작·새 기능 사용자 확인은 완료되지 않았다. 아래 내용은 저장소/지원 자료에 사용할 초안이며 공개한 서비스 실적으로 단정하지 않는다.

## 한 문장 소개

TruckWorks는 모형 트럭의 차체 생산을3D로 관찰하고, 읽기 전용 AI 에이전트가 공장 상태와 이벤트를 근거로 장애 원인을 설명하는 생산 시뮬레이터입니다.

## 짧은 소개

2026-10-11 화면 개편: 공장 전체→생산라인→설비/부품의 공간 탐색, 선택형 생산·고장·분석·복구 안내, 실제 AI 답변의 관련 설비 강조를 작성했다. 상시 로그·상세는 필요할 때 여는 정보창으로 이동했다. 실행·시각 확인은 대기다. 소재 선반은 배경 모형이고 조립 구역은 확장 예정 전시 공간이며 조립 생산 구현 실적으로 소개하지 않는다.

React 기반3D 관제와 FastAPI·SimPy 생산 엔진을 연결한 개인 프로젝트입니다. 차체1개에서 시작해 소재20개의 대기열·이동 예약·고장/복구로 확장했고, OpenAI·LangGraph 에이전트가 고정된 관측을 조회해 근거와 함께 설명하도록 작성했습니다. 생산/분석 이력은 PostgreSQL에 보관하며 방문자별 공장과 이력 소유권을 분리했습니다. 현재 로컬에서 사용자 실행 확인과 시연 준비를 진행 중입니다.

## 설명할 설계 선택

| 문제 | 작성한 방식 | 설명할 경계 |
|---|---|---|
| 화면/엔진 상태가 달라짐 | 서버 스냅샷이 상태를 소유하고3D는 수신 상태를 표현 | 정밀 물리나 실제 공장 데이터 동기화는 아님 |
| 이동 중 입력 공간 초과 | 입력 대기와 이동 예약을 합쳐 용량3으로 계산 | 데모의 생산 규칙이며 실제 설비 측정값 아님 |
| 고장 뒤 작업이 다시 시작됨 | 부품과 잔여 가공을 보존해 복구 후 이어감 | 모델이 자동 복구하는 기능은 없음 |
| 분석 도중 생산이 변함 | 요청 시작의 한 관측을 모든 읽기 도구에 재사용 | 도착한 답변은 과거 관측일 수 있음 |
| 모델의 잘못된 도구/인용 | 허용된 도구/입력을 검사하고 읽은 이벤트·설비에 인용 대조 | 인용의 존재 검사가 인과관계 검증은 아님 |
| 실패 응답의 사용량 유실 | 그래프 밖에서 수신 사용량과 도구 trace를 수집 | 공급자 미수신 사용량/실제 청구는 모를 수 있음 |
| 저장 지연으로 생산/응답 차단 | 비동기 저장 큐와 최신 상태 병합 | 메모리 큐라 강제 종료 무손실 보장 없음 |
| 방문자 조작/이력 혼합 | 익명 쿠키별 runner와 DB 소유자 조건 | 같은 프로필 탭은 공유, 계정 로그인은 없음 |
| 떠난 공장의 메모리 잔류 | 연결/요청 없는 엔진30분 정리와 사용 중 보호 | 엔진은 재개하지 않고 새 실행, DB 이력은 유지 |

이 표는 코드에서 설명할 수 있는 선택을 정리한 것이다. 성능 향상률이나 장애 방지 결과를 측정했다는 의미는 아니다. 실제 결과는 사용자 확인 후 별도로 추가한다.

## 소개할 수 있는 코드 범위

2026-10-11 자산 확장: 다섯 공정의 자체 Blender 편집 원본과 웹 GLB를 제작하고, 서버 진행률에 따른 가동과 실제 품질값에 따른 분리 가이드를 연결했다. ST-02 시각 품질에 대한 사용자 긍정 피드백을 받았으며 새 네 설비의 사용자 시각/가동 확인은 대기다. 검사 모형의 움직임을 실제 비전 검사 AI로 소개하지 않는다. 확인/재생성 안내는 EQUIPMENT_ASSETS.md와 assets/source-models/equipment/README.md를 따른다.

첫 공개 목표는 차체 생산라인과 읽기 전용 분석이다.3D 관제·생산 제어·설비 고장/복구·수량/부품 추적·WebSocket 재연결·생산/분석 이력·방문자 분리·유휴 정리를 작성했다. 세부 사용자 확인 상태는 [PROGRESS.md](PROGRESS.md)를 따른다.

실제 공장 연동·정밀 CAD/절삭 물리·시각 검사 AI·완제품 조립·트레일러·주문 최적화·자동 복구는 현재 제공 기능으로 소개하지 않는다.3D 설비는 공정별 역할을 표현하는 코드 기반 모델이며 실제 설비의 정확한 기계 모델로 주장하지 않는다.

## 공개 전에 채울 자료

| 자료 | 현재 상태 | 반영 조건 |
|---|---|---|
| 공개 데모 URL | 없음·호스팅 선택 보류 | 호스팅/예산 확정·사용자 배포 확인 |
| 소스 공개 링크와 범위 | 미정 | 사용자 공개 범위 선택 |
| 시연 영상 | 미촬영 | DEMO_GUIDE.md로 직접 실행·촬영 |
| 사용자 기능 확인 | 후속 기능 대기 | 실제 결과를 진행 기록에 반영 |
| 응답시간·정확도·3D 성능 | 미측정 | 조건·관측 수·결과를 함께 기록 |

URL·영상·측정값이 없을 때 임의의 예시 값을 실제 자료처럼 넣지 않는다. 첫 공개 후 소개 마지막 문장의 개발 상태를 실제 배포 결과에 맞춰 갱신한다.

## 다음 계획

로컬 기능 확인과 장애 분석 시연을 먼저 정리한다. 호스팅과 공개 범위는 이후 선택하며 첫 공개 뒤 바퀴·차축·운전석 공급과 조립으로 확장한다. 에이전트의 대안 비교와 사용자 선택 후 계획 적용은 별도 후속 단계다.
