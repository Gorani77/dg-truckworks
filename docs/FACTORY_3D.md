# 기본 3D 공장 장면

> 2026-10-08 후속 구현: 차체 1개의 5개 공정·4구간 이동·형상 변화·검사·적재 표시까지 작성했다. 아래 ST-01만 가동한다는 설명은 이전 단계의 기록이다. 현재 사용자 확인은 [SINGLE_PART.md](SINGLE_PART.md)를 따른다. 새 전체 흐름은 사용자 확인 대기다.

작성일: 2026-10-08 (Asia/Seoul)  
상태: 코드·의존성 선언 작성 완료, 사용자 설치·실행 확인 대기. 이전 단일 설비 백엔드·화면 연결 확인도 대기 상태다.

## 구현 범위

- Three.js + React Three Fiber + Drei로 바닥·컨베이어·5개 설비·작업대·상태 표시등을 작성했다. 외부 모델·텍스처·환경 맵은 사용하지 않는다.
- 사선으로 내려다보는 직교 카메라, 회전·확대·시점 초기화를 제공한다. 화면 크기에 맞춰 초기 확대를 계산한다.
- 설비를 클릭하면 기존 좌측 목록과 우측 상세의 선택이 함께 바뀐다. 키보드 선택은 기존 공정 목록과 2D 배치도 버튼을 사용한다.
- 서버 상태가 있을 때 라벨에 설비 상태를 표시한다. PROCESSING 표시등·진행 막대는 실제 remaining_process_seconds에서 계산한다. 화면이 별도로 생산 시간을 진행하지 않는다.
- current_part_id가 있는 설비에만 소재 블록을 표시한다. 현재 백엔드는 ST-01만 처리하므로 실제 소재는 ST-01에서만 나타난다. 완료 후 BLOCKED에서도 같은 소재가 남는다.
- 생산품과 별도로 프레임 형상 참고 모델을 배치하고 `형상 참고 · 생산품 아님`을 표시한다. 서버 생산량이나 완료 부품으로 세지 않는다.
- 2D 배치도 전환, 초기 3D 표시 실패 시 SVG 대체, 지연 로딩 중 SVG 표시를 작성했다. GPU 드라이버의 모든 오류나 context loss 자동 복구를 구현한 것은 아니다.
- frameloop="demand"로 상태·카메라 변화가 있을 때 렌더링하도록 했다. 성능 수치를 측정한 것은 아니다.

전체 공정 연결·소재 이동·가공 전후 형상 변화·품질 판정·실제 3D 자산 제작·WebSocket은 후속 작업이다. 이번 단계에서 생산 규칙이나 백엔드는 변경하지 않았다.

## 단위와 시각적 가정

### 2026-10-08 공정별 모델 개선 A 적용

사용자가 설비가 모두 비슷해 보인다고 지적했고, 코드 기본 도형으로 공정별 외형을 개선하는 A안을 선택했다. Blender 자산 제작 B안은 선택하지 않았다.

| 공정 | 새 외형 |
|---|---|
| ST-01 소재 투입 | 다단 투입 랙·수직 리프트·집게 |
| ST-02 형상 가공 | 전면·상부가 열린 가공실·횡축·가공 헤드·제어반·측면 창 |
| ST-03 구멍 가공 | 높은 드릴 컬럼·모터·스핀들·드릴 끝·고정 지그 |
| ST-04 품질 검사 | 개방형 검사 게이트·하향 카메라·센서 바·모니터 |
| ST-05 분리·적재 | 분기 테이블·사선 배출대·양품/불량 빈 적재함 |

설비 간격과 바닥을 넓히고 컨베이어를 작업대 높이로 올려 연결 구간의 롤러를 노출했다. 새 구도에 맞춰 카메라 중심과 초기 확대를 조정했다. 선택은 바닥 가장자리 강조로 구분하고 공정별 외형은 색보다 구조로 구분한다.

ST-01 리프트 표시는 실제 PROCESSING일 때 수신한 남은 시간의 진행률에 맞춰 변화한다. 실제 집게 물리·부품 운반을 재현한 것이 아니라 작업 중임을 나타내는 도식적 표현이다. 다른 공정 도구는 현재 서버가 처리 상태를 제공하지 않으므로 정지한다. 검사 결과·분기 방향을 꾸며내지 않는다. 투입 랙의 빈 슬롯은 장비 구조이며 재고 수량을 뜻하지 않고, 적재함에도 가짜 생산품을 넣지 않는다.

사용자 확인: 새로고침·시점 초기화 후 위 다섯 외형이 구분되는지, 설비 사이 롤러가 보이는지 확인한다. 설비 선택과 ST-01 소재 표시·처리 후 보관이 유지되고 다른 공정이 임의로 가동되지 않아야 한다. 카메라 회전·2D 전환·작은 화면의 라벨 겹침도 확인한다. 새 의존성은 없으며 이전 설치를 마쳤다면 재설치는 필요 없다. 코드 작성 완료·사용자 확인 대기이며 실행 검증은 수행하지 않았다.

장면은 X 길이·Y 높이·Z 폭을 사용하고 1 표시 단위를 100mm로 둔다. 소재·참고 프레임의 바깥 치수는 서버 설정의 180×60×12mm를 사용한다.

설비 크기·배치 간격·카메라·조명·금속 재질은 화면 표현용 초기 구현값이다. 형상 참고 프레임의 레일 두께와 연결부 위치는 도식적 비율이며 미확정 제작 치수·결합 좌표를 확정한 것이 아니다. 색상은 styles/tokens.css의 공통 토큰에서 읽고 배치·단위는 scene/sceneConfig.ts에서 관리한다.

## 나중에 사용자가 설치·확인

프론트엔드 개발 서버를 종료하고 `C:\project\truckworks\frontend`에서 실행한다.

```powershell
npm install
npm run dev
```

package.json에 @react-three/fiber 9계열, Drei 10계열, Three.js와 타입 0.180계열 범위를 선언했다. npm install이 실제 패키지와 package-lock.json을 갱신한다. 설치·잠금 파일 갱신은 Codex가 실행하지 않았다. React 19에는 Fiber 9를 사용하는 공식 안내를 따랐으며 실제 설치 조합의 검증은 사용자 수행 대기다.

백엔드 설치·실행은 [SINGLE_STATION.md](SINGLE_STATION.md), 기존 화면 데이터 확인은 [FACTORY_CONNECTION.md](FACTORY_CONNECTION.md)를 따른다.

1. 화면에 바닥·5개 설비·컨베이어와 형상 참고 프레임이 보이는지 확인한다.
2. 3D 설비를 클릭해 좌측 선택 강조·우측 상세와 같은 설비가 선택되는지 확인한다. 라벨과 설비가 읽히는지도 확인한다.
3. 드래그 회전·휠 확대 후 시점 초기화를 누른다. 초기 방향과 화면에 맞춘 확대 수준으로 돌아와야 한다.
4. 시작 전 서버 상태가 READY이면 공정 라벨이 대기 상태이고, 생산 중 소재 블록은 없어야 한다. 서버 미연결이면 `상태 수신 대기`이며 실제 소재가 나타나지 않아야 한다.
5. 소재 1개 처리 시작을 누르면 ST-01이 선택되고 소재 블록·처리 중 표시·진행 막대가 나타나야 한다. 약 2초 후 출력 대기 라벨과 소재가 유지돼야 한다. 양품·불량은 0이며 형상 참고 프레임과 혼동하지 않아야 한다.
6. 2D 배치도로 전환해 공정 선택이 유지되는지, 다시 3D로 돌아와도 현재 서버 소재 상태가 표시되는지 확인한다.
7. 서버를 종료하면 처리 소재와 실시간 상태가 사라져야 한다. 다시 실행하면 새 초기 상태를 표시해야 한다.
8. 창 크기를 줄여 설비가 보이는지와 라벨 겹침을 확인한다. 기기별 WebGL 지원·표시 실패 안내와 2D 전환은 사용자가 직접 확인한다.

설치 실패·렌더링 오류·시각적 문제를 알려주면 해당 결과를 바탕으로 수정한다. 초기 구도와 배치는 사용자 피드백 전의 구현안이다. 테스트·빌드·린트·설치·실행·브라우저 검증은 Codex가 수행하지 않았다.

## 코드 읽기와 공식 참고

### 2026-10-08 사용자 화면 보고에 따른 크기 수정

사용자가 첨부한 화면에서 장면이 영역 위쪽에 몰리고 잘리는 문제를 보고했다. 설치된 Fiber 소스를 읽었을 때 Canvas의 fallback은 WebGL 실행 중에도 canvas 태그의 대체 자식으로 DOM에 남는다. 따라서 `.canvasContainer:has(.layout)`은 실제 표시 실패 여부와 관계없이 매칭돼 부모 높이를 auto로 바꾸는 규칙이었다.

이 조건을 제거하고 Canvas wrapper를 지정된 높이의 영역에 absolute/inset:0으로 고정했다. 카메라·생산 규칙·의존성은 변경하지 않았다. 사용자 재확인 대기이며 Codex는 실행·브라우저 검증을 수행하지 않았다.

프론트엔드 화면을 새로고침한 뒤 `시점 초기화`를 누르고 5개 설비가 영역 중앙에 잘리지 않고 보이는지, 창 크기를 바꾸어도 장면이 영역을 채우는지 확인한다. 필요하면 2D→3D 전환 후 다시 확인한다. 수정 때문에 별도로 패키지를 재설치할 필요는 없다.

`FactoryDashboard.tsx`에서 stationStates를 `FactoryViewport.tsx`로 전달 → lazy 로딩과 2D 전환·오류 대체 → `FactoryScene.tsx`의 Canvas·카메라·조명·배치 → `StationModel.tsx`의 선택·상태·소재 표시 순으로 읽는다. 좌표·팔레트는 `sceneConfig.ts`, 오류 경계는 `SceneBoundary.tsx`다.
