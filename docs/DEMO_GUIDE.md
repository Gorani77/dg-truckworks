# 로컬 데모와 시연 준비

작성일: 2026-10-11 (Asia/Seoul). 시연 안내·대본 초안 작성 완료, 사용자 직접 실행·확인·촬영 대기. Codex는 설치·테스트·빌드·린트·DB 변경·서버 실행·HTTP·브라우저 검증·모델 호출·영상 촬영을 수행하지 않았다.

## 시작 전 준비

2026-10-11 화면 개편 후에는 [공간 탐색형 체험 안내](IMMERSIVE_EXPERIENCE.md)를 먼저 따른다. 기본 진입은 공장 전체이며 차체 라인 표지판으로 진입한다. 아래의 초기화·시나리오 선택은 하단 **생산 설정**, 설비 상세/고장·복구는 **설비 클릭**, 질문·수동 조회는 **AI에게 질문**, 이벤트/생산/분석 이력은 상단 **기록**에서 연다. AI 수동 조회는 질문창의 접힌 상세 영역에 있다. 첫 화면의 안내 체험으로 생산→고장→분석→복구를 따라갈 수 있다. 새 화면 촬영·확인은 아직 수행하지 않았다.

루트 README.md와 backend/README.md의 기존 로컬 실행 안내를 따른다. DB를 사용하면0003_visitor_ownership까지 적용하고, 이전 WebSocket/OpenAI 의존성을 준비하지 않았다면 uv sync가 필요하다. API는8010, 프론트엔드는 Vite가 출력한 주소를 사용한다. localhost와127.0.0.1 중 한 호스트를 일관되게 쓴다.

화면이 연결된 뒤 READY·소재20개인지 직접 확인한다. 다른 탭은 같은 쿠키의 공장에 영향을 줄 수 있으므로 시연할 탭을 정한다. 녹화에는 실제3D 영역·생산 제어·선택 설비 상태·이벤트/분석 근거를 담는다. 환경변수 편집기·키·쿠키 원문·DB 암호 화면은 담지 않는다.

자연어 분석은 서버 키 설정과 실제 호출이 필요하다. 원격 비용이 발생하므로 아래에서 수동 도구 조회와 별도의 단계로 구분한다. 키가 없거나 실제 호출을 보류하면 생산과 수동 조회까지만 시연하고 자연어 분석은 미확인으로 남긴다.

## 1. 차체 하나로 공정 흐름 설명하기

1. 필요하면 `실행 초기화`를 누른다. 시나리오에서 `차체 1개 전체 공정 / 26초`를 선택하고 `차체 1개 생산 시작`을 누른다.
2. 투입 → 형상 가공 → 구멍 가공 → 품질 검사 → 분리/적재로 같은 부품이 이동하는 모습을 보여준다. 선택 설비의 상태/남은 시간과 이벤트를 함께 본다.
3. 정상 조건의26초는 설계상 공정22초+이동4초다. 성능 벤치마크가 아니다. 고장/정지 없이 완료되는지와 소재19개·저장된 부품1개·재공0을 직접 확인한다. 품질은 실제 수신 결과대로 설명한다.

설명 예시: “생산 상태는 서버의 SimPy 엔진에서 계산하고3D 화면은 수신한 설비와 부품 상태를 표현합니다. 처리시간은 실제 공장 측정값이 아니라 이 프로젝트에서 정한 규칙입니다.”

## 2. 연속 생산 중 고장과 대기 설명하기

1. 초기화 후 `차체 20개 연속 생산 / 입력 대기 3개`를 선택하고 `차체 20개 생산 시작`을 누른다.
2. `ST-02` 형상 가공 설비를 선택한다. 가공 중 표시를 직접 보고 `고장 발생`을 누른다. 현재 부품과 남은 시간이 보존되는지 본다.
3. 잠시 생산을 진행해 앞쪽 대기/예약이나 출력 대기가 생기는 모습을 확인한다. 다른 설비/이동은 가능한 범위에서 계속 진행해야 한다. 대기 공간 때문에 멈춘 정상 설비를 추가 고장이라고 설명하지 않는다.
4. 상태를 설명할 시점에 `일시정지`로 관측 화면을 고정한다. 공장 일시정지와 설비 고장은 서로 다른 상태다. 일시정지했다고 고장이 복구되지는 않는다.

설명 예시: “ST-02를 수동 고장 상태로 만들었습니다. 고장 설비는 남은 작업을 보존하고, 앞쪽 공간이 차면 정상 설비도 출력 대기에 들어갈 수 있습니다.”

## 3. 비용 없는 도구 조회와 자연어 분석 구분하기

먼저 `운영 분석`의 `선택 설비 상태`, `선택 설비 최근 이벤트`, `선택 설비 대기·예약`을 눌러 실제 자료를 읽는다. 이 버튼들은 OpenAI를 호출하지 않는다. 조회 결과는 관측 시점 자료이며 자동 갱신되지 않는다.

자연어 분석까지 직접 확인할 경우 질문을 입력하고 `분석 요청`을 누른다.

> ST-02 고장이 현재 생산과 대기에 어떤 영향을 주고 있는지, 조회한 상태와 이벤트를 근거로 설명해줘.

답변 문구를 미리 정답처럼 채우지 않는다. 실제 관측 버전/시각·도구·근거 이벤트·관련 설비·한계를 읽고 화면 자료와 맞는지 판단한다. 모델이 고장을 복구하거나 생산을 제어하지 않는지도 확인한다. 부정확한 설명은 실패/개선할 결과로 기록한다. 사용량·추정 비용과 실제 청구는 구분한다.

공급자 연결 실패/시간 초과 시 오류 안내를 그대로 보여준다. 수동 조회 결과로 설명을 이어갈 수 있지만 이를 모델 답변 성공으로 기록하지 않는다. 영상에 답변 대기 구간을 줄였다면 편집/배속임을 표시하고 응답시간 측정 자료로 쓰지 않는다.

## 4. 복구와 저장 이력 보기

1. 일시정지 상태에서 `복구`를 눌러 ST-02 고장을 해제한다. 공장 시간이 아직 멈춰 있다면 `재개`를 눌러 남은 작업부터 이어가는 모습을 본다.
2. 생산을 끝까지 진행한다면 양품+불량 합계20·재공0·소재0인지 확인한다. 정지/고장을 넣은 실행을 기본 정상 생산시간178초와 직접 비교해 성능 결과로 주장하지 않는다.
3. DB를 사용하면 생산/분석 이력에서 `이력 새로고침`을 누른다. 저장된 실행·부품 이벤트·분석의 동일 ID/관측/근거를 본다. 큐 제출 직후라 아직 없으면 커밋 완료를 확인한 뒤 다시 조회한다.
4. 새 실행을 보여주려면 초기화 후 기존 이력이 남는지 확인한다. 이력은 과거 상태 조회이며 과거 엔진 재개 기능은 아니다.

## 5. 방문자 분리와 재연결 보여주기

일반창 A와 별도 시크릿창 B에서 같은 주소를 열어 서로 다른 run_id를 확인한다. A의 시작/고장/초기화가 B에 반영되지 않아야 한다. 같은 A 프로필의 새 탭은 같은 실행이어야 한다. 구체적인 타인 이력 상세404는 VISITOR_SESSIONS.md를 따른다.

연결 중단/복원은 FACTORY_STREAM.md, 유휴 정리는 IDLE_FACTORIES.md 순서로 별도 확인한다.30분 대기를 짧은 촬영 장면으로 조작해 실제 경과처럼 표시하지 않는다. 임시15초 환경변수로 확인했다면 영상/기록에 그 조건을 명시한다.

## 사용자가 남길 결과 양식

아래는 빈 기록 양식이다. 실제로 수행한 항목만 채워 공유하면 PROGRESS.md와 소개 자료에 반영한다. 환경변수 원문/쿠키/비밀키는 넣지 않는다.

```text
실행 날짜/환경:
DB 사용 여부 / migration 적용 여부:
1개 생산: 수행 여부 / 완료 상태·수량 / 오류
20개 생산·고장·복구: 수행 여부 / 부품 보존·대기 / 오류
수동 도구: 수행 여부 / 화면과 일치 여부
실제 모델 분석: 수행/미수행 / 분석 ID / 근거 일치·부정확한 설명
생산/분석 이력: 수행/미수행 / 초기화 뒤 유지 여부
방문자 분리·재연결·유휴 정리: 각각 수행/미수행 / 결과
촬영: 미촬영 또는 실제 파일 위치 / 편집·배속 조건
다음 수정이 필요한 점:
```

응답시간/프레임률/정확도 등을 측정하려면 시작/종료 기준·장비/브라우저·시나리오·관측 수를 먼저 정한다. 한 번 성공한 화면을 전체 안정성/정확도 수치로 바꾸지 않는다.
